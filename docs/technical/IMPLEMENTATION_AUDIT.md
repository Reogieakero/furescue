# FurEscue — Implementation Audit

**Date:** August 22, 2026
**Scope:** Traceability of every objective in `docs/study/OBJECTIVES.md` (OBJ-1…OBJ-10) and every functional requirement in `docs/study/REQUIREMENTS_SPECIFICATION.md` (community users REQ-C*, admins REQ-A*, system REQ-S*) against the code actually present in this repository.

*(No row is ❌ because every requirement has at least a functioning backend foundation; the partial grades reflect missing user-facing halves, detailed above.)*

### Prioritized gaps (biggest first)

1. **Entire community-facing application surface.** The largest single gap: residents/reporters/adopters have zero functional pages. Reporting, animal browsing, adoption applications, notification inbox, and e-learning consumption all exist as complete REST APIs (`src/Controllers/*`) with no HTML/JS consuming them — the only non-admin surfaces are a marketing landing page and a login form. This blocks OBJ-1/2/6/7/8 and REQ-C2/C4/C5/C6/C7 outright.
2. **Registration UI (and auth-surface coherence).** No sign-up screen exists ("Sign up" → `#`); JWT register/login APIs and the session-login page operate as parallel, unintegrated auth systems. Related defects: admin login redirects to nonexistent `/admin/index.php`; Google Sign-In button unwired despite a working backend endpoint (`AuthController::google`). Blocks REQ-C1.
3. **Real-time notification delivery + resident inbox.** Notifications persist correctly but reach users only on page reload; add polling/WebSocket/SSE and (for residents) any inbox surface. Affects OBJ-4, REQ-C6, REQ-S4.
4. **Broken/stub admin interactions.** `POST /cases/{id}/proof` is called by `case-detail/components/events.js` but has no backend route (button always errors) even though `cases.resolution_photos` exists (migration 000007); sidebar links Listings/Applications/E-Learning/Messages/Notifications have no targets; topbar search and profile-menu items are inert. Quick wins that make existing screens honest.
5. **Report media upload.** Wire the existing multipart machinery (`DocumentsController` pattern + `/uploads/` serving) to reports, and decide video scope. Affects REQ-C3.
6. **Admin-initiated notifications/broadcasts.** Only system-event notifications exist; REQ-A6 needs a compose/broadcast capability (API + small UI).
7. **E-learning authoring + consumption UIs.** Module editor (admin) and lesson reader/progress tracker (residents) — the data layer is done. Affects OBJ-8, REQ-C7.
8. **Rescuer duty-status toggle.** `on_duty` is *enforced* during case assignment (`CaseController::assign`) and seeded, but no endpoint or UI toggles it — duty changes currently require DB edits [uncertain whether handled outside the repo].
9. **3D profiling substance.** Beyond nullable `model_3d_url`/`photo_360_set` columns there is no viewer, upload, or seeding. Either build viewer + capture flow or descope OBJ-9.
10. **Analytics exports & dedicated pages.** CSV/PDF export of trends/stats (OBJ-5/REQ-A5 caveat); sidebar promises Analytics/Settings/Listings pages that don't exist.
11. **Production hardening visible in code.** Open CORS, unauthenticated dev `dbtool/index.php`, `.env.example` secrets hygiene, PHPUnit coverage limited to 6 unit classes (no endpoint/integration tests), and drift between `docs/technical/SYSTEM_REPORT.md` and the actual repo layout (documented `frontend/`–`backend/` split does not exist).
