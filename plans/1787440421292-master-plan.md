## Page Folder Convention (applies to ALL sub-plans)

Every **new** page gets its own folder instead of a flat `public/<page>.php`:

- Main entry: `public/<page>/index.php` → URL `/page/`.
- Sub-pages of the same section: extra `.php` files in that folder (e.g. `public/animals/detail.php` → URL `/animals/detail.php?id=7`).
- Page-specific assets live INSIDE the page folder: `public/<page>/js/*.js`, `public/<page>/css/*.css` (if ever needed), page-local partials too.
- Shared stuff does NOT move: chrome partials stay in `public/includes/` (`resident-shell.php`), shared libs/components stay in `public/js/lib/` + `public/js/components/`, design tokens/classes stay in `public/css/input.css`.
- Reference assets with absolute paths from markup (`<script type="module" src="/animals/js/animals.js">`) so links survive both `/animals/` and `/animals/detail.php` URLs.
- Admin equivalents nest under `public/admin/<page>/index.php` (URL `/admin/<page>/`).
- Existing pages (`auth/login.php`, `admin/cases.php`, ...) keep their current paths; only NEW pages follow this convention.

**Pre-flight (do ONCE before launching sub-plans, owns `public/index.php` + `tailwind.config.js`):**
1. Extend `public/index.php`: when `realpath()` resolves the request URI to an existing directory under `public/` that contains an `index.php`, redirect extensionless requests (`/animals` → `/animals/`) and `return false` so the built-in server serves that directory's `index.php`. Without this, every new folder page 404s into the API router.
2. Add Tailwind `content:` globs for the new folders (`public/{report,reports,animals,adoptions,listings,learning,messages,notifications}/**/*.{php,js}` and `public/admin/{analytics,notifications}/**/*.{php,js}`) or classes used only there get purged on rebuild.
